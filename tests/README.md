The unit tests use Node's built-in runner, so there's nothing to install beyond the app itself. They cover the code with logic in it; the Electron wiring is covered by the smoke run instead, because mocking Electron would test the mock.

| File | What it pins down |
|:---|:---|
| [**tree.test.js**](tree.test.js) | Hub id to path (base, home, virtual), click actions (files open as documents), the right-click menu for folders, files and virtual nodes, terminal folders, a 20,000-deep tree flattening without a stack overflow, search ranking and limits, bookmark flattening. |
| [**url.test.js**](url.test.js) | Address-bar input: URLs kept, Windows paths to `file://`, loopback to `http`, hosts to `https`, everything else to a search; `javascript:` and `data:` refused; a `file:` URL only from the app or another local file. |
| [**recent.test.js**](recent.test.js) | Newest first, de-duplicated by type and target, capped at 50, and a hand-edited file can't inject bad entries. |
| [**mcp.test.js**](mcp.test.js) | MCP server: exact-token and loopback-host checks, protocol negotiation, tool listing and calls, JSON-RPC errors, and a real HTTP server refusing a missing or wrong token (401), GET (405), bad JSON (400), a foreign `Origin` (403) and an unsupported protocol version (400). Malformed `params`, `arguments`, ids and tool names get JSON-RPC errors; `structuredContent` is only ever an object; a failure inside the handler is answered and the next request works; a client that disconnects aborts the tool it waits on; and a strict-client session checks every reply's shape. |
| [**tools.test.js**](tools.test.js) | MCP tools through `handleMessage`: `list_tabs`, `read_tab` (the active tab or a named one, clipped with a `truncated` flag, bad ids and sizes refused), `list_terminals`, `terminal_read` (the showing terminal or a named one, escapes stripped, last N lines, nothing open), `cron_tasks` (the list, a missing setup as a tool error) and `cron_run` (the id trimmed and passed on, the result returned, denial and unknown ids as tool errors, bad ids refused before asking), `sidebar_search` (absolute paths, bookmarks, recent, per-group limits, partial results with an `errors` list when Hub is down) and `recent` (type filter, limit); blank, oversized or non-string queries and out-of-range limits come back as tool errors. `open_tab` (address-bar text to a URL, background tabs; local files, about: and extension pages refused) and `open_file` (VS Code or reveal; absolute paths, `..`, UNC, virtual `@` nodes, control characters and default-app opens refused, Hub errors surfaced). `terminal_run` (trimmed command and optional `cwd` passed on, terminal and folder reported, denial as a tool error; newlines, tabs, escapes, bidi and zero-width characters, and relative, UNC or hidden-character folders refused before anything is asked). Also the shared `searchAll`. |
| [**chat.test.js**](chat.test.js) | The chat: key and model from the environment with no default model, blank and oversized messages refused, MCP tools and results translated to and from the Messages API, roles kept alternating after a turn that stopped early, attachments (page and terminal only, read through `read_tab` and `terminal_read` before the post, a failed read noted rather than dropped), the tool loop (tool errors and thrown tools passed to Claude, every `tool_use` answered, the 10-round cap), API errors surfaced, streamed replies put back together whatever the chunk size (split characters, empty text, an `error` event, broken tool input and a cut-off stream included) and shown as deltas, whole turns trimmed past the token budget, a saved `chat.json` checked (hand-edited and half-written files give an empty conversation) and replayed with attachments folded, a turn driving a real MCP server over HTTP with its token (calls logged, a denial returned as an error, a wrong token refused), and Stop: during the model request, during a tool call (the open `tool_use` answered as stopped), and a deadline failing one call without ending the turn. |
| [**confirm.test.js**](confirm.test.js) | Confirmations: payload shown with an id, settled once, asks independent, unanswered asks time out to null and tell the UI, late answers ignored, an ask whose asker goes away withdrawn; `isFreshRunTarget` taking only a running PowerShell opened for the ask in its folder. |
| [**docs.test.js**](docs.test.js) | Document pages: URLs mirroring Hub ids so relative links resolve, round-trips with spaces and `#`, refused hosts and virtual ids, `..` collapsed, web pages refused navigation to `acc://doc` and every page refused `acc://run`, escaping, folder listings, the run page (output escaped, no output, a failed fetch), and headers that forbid scripts and framing. |
| [**shells.test.js**](shells.test.js) | Shell profiles: PowerShell 7 first, missing shells skipped, a per-user Git install found, a PATH fallback, unknown ids (including paths and arguments) falling back to the default; and the native-menu item check. |
| [**mcplog.test.js**](mcplog.test.js) | The MCP call log: tool calls, tool and JSON-RPC errors, junk messages, clipped arguments, refusals, the file line (a `terminal_run` command as its length, URL query strings cut, checked with sentinel values), the capped list, and a real server reporting a refused call, a tool call and a notification through `onCall`. |
| [**cronsole.test.js**](cronsole.test.js) | Cronsole: the server path and UI origin from the environment (non-http UIs refused), the pinned-tab URL match by exact origin, the handshake, `list_tasks` and `run_task` (the id passed on, a result or its text returned, a tool error thrown, ids checked) against a fake stdio server that answers in split chunks with stray lines mixed in, JSON-RPC errors, timeouts and a dying process, tool errors and malformed rows, `get_task_history` and `get_run_output` (arguments, empty and malformed history, at most five runs), `acc://run` URLs round-tripped and refused, and the sidebar's next-run, paused, missing and failed rows and its run rows. |
| [**session.test.js**](session.test.js) | Saved tabs: only allowed schemes, no blank pages, order kept, capped at 30; a bad active index falls back to the last tab. Tab cycling wraps round the strip, and Ctrl+1 to Ctrl+9 follow Chrome's rule. |
| [**settings.test.js**](settings.test.js) | `settings.json`: neutral defaults for a missing or broken file, the Hub URL http(s) only and on this machine unless `ACC_HUB_REMOTE=1`, with `ACC_HUB_URL` winning, quick links validated and capped, the default link following the Hub URL. |
| [**permissions.test.js**](permissions.test.js) | Pages get fullscreen, pointer lock and sanitized clipboard writes; media, location, notifications, MIDI, screen capture, clipboard reads, devices and anything unknown are refused. |
| [**demo.test.js**](demo.test.js) | The browser demo: the source bar and the mock load before `app.js`, every path relative, a moved anchor fails the build; renderer imports are relative; the mock answers every call the preload exposes, so a new IPC call can't ship without one; no `fetch`, XHR, WebSocket or beacon in the demo; the fake terminal's echo, prompt and canned output; tab history and reopen; the confirm-bar ask logged as denied without a click. |
| [**output.test.js**](output.test.js) | Terminal output cleaning: colours, titles and hyperlinks stripped, carriage returns and PSReadLine's redraws (absolute column, erase line, cursor back) resolved to what the screen shows, control characters dropped, tabs kept, the last N lines without trailing blanks, the capped buffer. |
| [**events.test.js**](events.test.js) | Hub's `/api/events` stream: `change` events with their data, the `retry` preamble and heartbeat comments ignored, events and multi-line data split across chunk boundaries, several events in one chunk, CRLF line endings. |
| [**favorites.test.js**](favorites.test.js) | Starring a page in Hub: added to the front of the Favorites bar, removed from anywhere on toggle, blank names filled with the URL and long ones capped, non-web URLs and malformed roots ignored, exact web-URL matching, and no mutation of the input tree. |

| [**links.test.js**](links.test.js) | Links in terminal output: a dev server's address and its position, bare loopback hosts with a port made `http://`, several links on one line, trailing punctuation dropped but balanced brackets kept, other schemes, portless hosts, lookalikes and bad ports ignored, empty and non-string input. |

## Checking the real app

| Command | What it does | Takes |
|:---|:---|:---|
| `npm run smoke` | Launches the app on a throwaway profile (`--profile` for the real one), opens example.com and a terminal, expands the first folder, searches "README", logs the counts, calls the MCP server without and with the token from `mcp.json` (expects 401 then 200) opens a background tab with `open_tab` and logs what `list_tabs`, `sidebar_search` and `recent` return, calls `terminal_run` and clicks Run on the confirm bar (the command prints `ACC_MCP_URL`, so `shell.png` shows the terminal got it), then reads that output back with `list_terminals` and `terminal_read` and the example.com page with `read_tab`, calls `cron_tasks` (the list, or the setup note when `ACC_CRONSOLE_MCP` isn't set), types a word into the find bar and reads the match count, lists the shells, starts and kills a Command Prompt session, clicks a Markdown file, checks the document page it lands on (title, headings, images, no second sidebar) and saves `doc.png`, checks the MCP panel lists the same calls as the end of `mcp.log`, opens the Chat tab, toggles + page on and off, and logs what it tells the user (model or missing variables, never the key), opens the Cron tab and logs how many Cronsole tasks it lists (or what it says when `ACC_CRONSOLE_MCP` isn't set), unfolds the first task with a last run, opens its newest run and logs the `acc://run` page's title, facts and output length, clicks Open Cronsole twice and checks there's one pinned tab and it's first, saves `shell.png` and `tab.png` to `.smoke/`, and quits. Each step is a named check, printed as PASS, FAIL, SKIP or WARN and written to `.smoke/summary.json`. Checks that need Project Hub or Cronsole count only with `--live` (`npm run smoke -- --live`) and are skipped otherwise; a screenshot that fails (a locked or hidden display) is a warning. Exits 1 when a check fails, when the app quits without running them (another instance on the same profile), or after 120 s. | 30 to 80 s |
| `npm run spike:extensions` | Installs LastPass and Rakuten from the Web Store, loads a shop page, and logs each extension's errors. Rerun on every Electron upgrade. | about 60 s |
| `npm run demo` | Builds the browser demo into `_site/`. Preview it with any static server (`python -m http.server -d _site`) and check the sidebar, a terminal (`npm test`), and the confirm bar after six seconds. | a second |

> [!NOTE]
> Both commands open a real window on a throwaway profile under `%TEMP%` (deleted afterwards, with only your `settings.json` copied in), so they run beside an open copy of the app and leave your history, logs and extensions alone. `npm run smoke -- --profile` uses the real profile in `%APPDATA%\ai-command-center` instead; it then won't run while the app is open.
