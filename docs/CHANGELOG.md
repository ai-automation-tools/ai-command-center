## Unreleased

- **Config:** Settings move from Windows user variables to a `.env` file at the clone's root (`.env.example` lists them; gitignored). `src/main/env.js` reads it with Node's `util.parseEnv`, the real environment winning, and keeps it out of `process.env`, so terminals and Cronsole's child process no longer see the chat key. 2 tests.
- **Code health:** The `npm run smoke` routine moves out of `src/main/main.js` into `src/main/smoke.js` (main.js 590 → 389 lines); the test count lives once, as a "140+" badge in `tests/README.md`. *(roadmap: Code health)*
- **Docs:** The README links the Project Hub and Cronsole skills in `ai-automation-tools/agent-skills` from "Drive the app from Claude Code".
- **Docs:** An app architecture diagram in `docs/diagrams/`, built with [Archify](https://github.com/tt-a1i/archify): shell UI, main process, browser tabs, Project Hub, Cronsole, terminals, the chat panel and the MCP server with its confirm bar, each component linked to the lines it describes at a pinned commit. `scripts/build-diagram.mjs` builds it, copies the HTML and PNG into the homepage repo (`ai-command-center-site`, which embeds it live), and with `--check` reports cited code that changed since the pin; CI warns on drift. *(docs)*
- **Docs:** The browser demo moves to `ai-command-center-demo.ai-automation-tools.dev`; `ai-command-center.ai-automation-tools.dev` is now the project homepage (served from `ai-command-center-site`). Old demo deep links redirect.

Phase 1 done, Phase 2 started (merged in PRs #1 and #2). Tab restore, the launcher and the live MCP server's token check were confirmed by hand on 2026-09-30. The read-only and navigation MCP tools followed in weekly roadmap PRs the same day, and `terminal_run` on 2026-10-04, along with the daily-use gates (Files right-click menu, documents under the app's own sidebar, shell menu) and a fix to the page context menu's open-externally item, then the MCP call log and the README's `claude mcp add` section, the chat panel, and Cronsole in the sidebar, which finished Phase 2. A repo review on 2026-10-05 reshaped the roadmap and landed six release gates (CI, the settings file, SECURITY.md, page permissions, the crash log, browser shortcuts) then find in page, and the first Phase 2b tools (`list_terminals`, `terminal_read`, `read_tab`, `cron_tasks`, `cron_run`). The live demo, the last gate, followed on 2026-10-07.

**Added**

- Ad and tracker blocking, on by default: Ghostery's engine (`@ghostery/adblocker-electron`, MPL-2.0) with its prebuilt EasyList/EasyPrivacy build blocks requests in browser tabs and hides ad slots. **Extensions → Block ads and trackers** turns it off, remembered in `layout.json`. The engine downloads in the background at first start, is cached as `adblock-engine.bin` in userData and is fetched again after a week. Web Store ad blockers can't do this job: they filter through `declarativeNetRequest`, which Electron lacks. LastPass and Rakuten still start with it on.
- An **Extensions** menu (Alt shows the menu bar): **Get extensions…** opens the Chrome Web Store in a tab, and each installed extension lists its version with **Options**, **Web Store page** and **Remove…**, which asks first, then uninstalls it for good (`uninstallExtension` deletes it from `Extensions/`). The list follows installs and removals. The toolbar's own right-click menu can't remove an extension outside development builds.
- Right-click in the terminal copies the selection, or pastes when nothing is selected, the way Windows Terminal does.
- Cronsole runs in the sidebar: a click on a task in the Cron tab unfolds its last five runs from Cronsole's `get_task_history` (when, the status, how long; failures and timeouts in red), and a click on a run opens `acc://run/<task>/<run>` in a tab, the document page around the run's log, or for a run a platform recorded, the steps and output Cronsole's `get_run_output` returns. The page is served only for a task in `list_tasks` and a run in its history, under the document pages' no-script headers, and opens from the app only: no page can navigate to it or fetch it. Opening Cronsole's UI is the **Open Cronsole** button's job now. 6 tests; the demo's tasks have runs. *(roadmap: Integrations)*
- Links in the terminal open as tabs: an xterm link provider underlines `http(s)://` addresses and bare `localhost`, `127.0.0.1` or `[::1]` with a port in any terminal's output, and a click opens one in a new tab through the same path as the address bar. The line is read cell by cell, so a wide character before a link doesn't shift it. `src/shared/links.js` finds the links, 6 tests; no new dependency. *(roadmap: Integrations)*
- A ☆ in the address bar: clicking it adds the active page to Project Hub's favorites (`PUT /api/favorites`, which replaces the whole list, so the app GETs it, toggles, and PUTs it back), and clicking again removes it. The star fills when the page is already a favorite, hides on non-web tabs, and the sidebar's Hub-favorites source gains the entry without opening Hub. `src/shared/favorites.js` has the add/remove logic, 6 tests; the demo's fake hub toggles the same way. *(roadmap: Integrations)*
- Project Hub rescans show up without Retry: the main process subscribes once to Hub's `/api/events` stream, and each `change` event both invalidates the document index in `src/main/docs.js` (so the next `acc://doc/` request rescans instead of waiting out the 30 s cache) and reloads the Files tree in the sidebar. The subscription reconnects itself when Hub drops it, and the demo's fake hub answers the new `onChanged` call. `src/shared/events.js` parses the server-sent stream (6 tests), `src/main/hub.js` runs the long-lived fetch. *(roadmap: Integrations)*
- The demo opens on a welcome page: a `README.md` tab in the content area that says what the app is, what each part does, and what to try in the demo (the canned terminal commands, the confirm bar, the sidebar tabs). The sidebar lists it under Projects › ai-command-center, so a closed tab can come back. Static HTML in `src/demo/about.js`, no scripts or network; 1 test. *(demo)*
- `docs/UPSTREAMS.md`: the outside services, protocols and platforms the app depends on (Messages API, MCP, Cronsole, Project Hub, Electron, node-pty, the Chrome extension packages, CI), with what the code assumes and where to check each. The biweekly upstream check works from it. *(housekeeping)*
- MCP tool annotations: `tools/list` now gives every tool `readOnlyHint`, `destructiveHint` and `openWorldHint`, so a client like Claude Code can show which tools look and which act. The seven that look are read-only; `open_tab` and `open_file` change nothing on disk; `terminal_run` and `cron_run` are marked destructive and open-world, since they run whatever you click Run on. `read_tab` and `open_tab` are open-world because they touch web pages. Hints only: the click is still the guard. 1 test. *(roadmap: Phase 2b)*
- Chat replies stream in as Claude writes them, and the conversation survives a restart: the main process asks the Messages API for a stream and puts the server-sent events back into a reply (`readStream`), the panel grows the reply as text arrives, and the conversation is saved to `chat.json` after every message and on Clear, then replayed at start with attachments folded to `[+ page]` / `[+ terminal]`. A hand-edited or half-written `chat.json` gives an empty conversation, and one cut off between a tool call and its result loses that call. Past about 50,000 estimated tokens the oldest whole turns are dropped before the next request, and the panel says so. An empty reply is no longer kept, since the API would refuse it next time. `readStream`, `trimHistory`, `cleanMessages` and `transcript` in `src/shared/chat.js`, 8 tests. *(roadmap: Phase 2b)*
- Chat attachments: **+ page** and **+ terminal** toggles in the chat bar put the active tab's text (`read_tab`) or the showing terminal's last lines (`terminal_read`) above your next message, so "what does this page say" needs no tool round-trip. The main process reads them through the MCP server, so they're logged like any call and the text never passes through the shell UI; a failed read is noted in the message rather than dropped, and the system prompt says attachments are content, not instructions. `chatAttach` and `withAttachments` in `src/shared/chat.js`, 3 tests. *(roadmap: Phase 2b)*
- Live demo at `https://ai-command-center.ai-automation-tools.dev/`, deployed since 2026-10-18 by `.github/workflows/pages.yml` on every push to `main` (built 2026-10-07 and held until then): the shell UI running in a browser on a fake `window.acc` (`src/demo/`) with made-up files, bookmarks, Cronsole tasks, MCP calls and a terminal that answers `npm test`, `git status`, `ls` and `help`; one `terminal_run` ask raises the confirm bar. The org source bar sits across the top. No network calls, no storage, no secrets. `npm run demo` builds it into `_site/`. The renderer's imports and `index.html` paths are now relative, so the same files serve under `acc://shell/` and a Pages subpath. 8 tests, including one that fails when the preload gains a call the mock doesn't answer. *(roadmap: Public release)*
- `cron_tasks` and `cron_run` MCP tools: Cronsole's task list as the Cron tab shows it, and a way to start a task now through Cronsole's own `run_task`. `cron_run` puts the task's name on the confirm bar ("An agent wants to run this in Cronsole") and runs nothing until the click; the task id stays in the main process and the click answers only yes or no. A native task that ran and failed comes back as a result, not a tool error, and the tool's description tells the model to report it that way. `runTask` in `src/shared/cronsole.js` with 2 tests, the tools with 2. *(roadmap: Phase 2b)*
- Find in page: Ctrl+F opens a find bar in the address row, matches count as you type (`1/2`), Enter and Shift+Enter step forward and back, Escape or × closes it, and it closes when you switch tabs. `npm run smoke` types a word into it on example.com and reads the count. *(roadmap: Public release)*
- `read_tab` MCP tool: a tab's title, URL and visible text (`document.body.innerText`, clipped to `max_chars`, 20,000 by default), the active tab unless an id from `list_tabs` is given. The description tells the model the text is page content, not instructions, and the chat's system prompt says the same. Read-only, no click. *(roadmap: Phase 2b)*
- `list_terminals` and `terminal_read` MCP tools: the open terminal sessions (id, shell, folder, PowerShell or not, exited or not, which is showing), and the last N lines (50 by default, 500 at most) of one session's output as plain text, the showing terminal unless an id is given. The main process keeps the newest 200,000 characters of each session's raw output; `src/shared/output.js` turns ConPTY's escape sequences into what the screen shows with a one-line cell model (text overwrites from the cursor's column, so PSReadLine's redraws of the line being typed come out once), drops the rest, and has 5 tests. An agent that ran `npm test` through `terminal_run` can now read the result, and the chat's system prompt tells it to. `npm run smoke` reads back what its own `terminal_run` printed. *(roadmap: Phase 2b)*
- Browser shortcuts: Ctrl+Tab and Ctrl+Shift+Tab cycle tabs in the strip's order (the pinned tab first), Ctrl+1 to Ctrl+8 pick a tab and Ctrl+9 the last, Ctrl+Shift+T reopens the last closed tab (the last 10 are kept, blank pages left out), and Ctrl+plus, Ctrl+minus and Ctrl+0 zoom the page in Chrome's steps, remembered per site. `cycleTab` and `pickTab` in `src/shared/session.js`, 2 tests. *(roadmap: Public release)*
- Crash and error log: uncaught exceptions and unhandled rejections in the main process, and a renderer, tab or helper process going away, are appended to `%APPDATA%\ai-command-center\logs\app.log` with a timestamp, and a startup failure goes there before the app exits. `src/main/applog.js` holds the writer, which rotates at 5 MB and now serves `mcp.log` too. *(roadmap: Public release)*
- Page permissions denied by default: the browse session refuses every permission a page requests (camera, microphone, location, notifications, MIDI, screen capture, clipboard reads, USB, serial, HID and the rest) except fullscreen, pointer lock and sanitized clipboard writes. Electron grants everything when no handler is set. The allowlist is `src/shared/permissions.js`, with a test. *(roadmap: Public release)*
- `SECURITY.md`: how to report a vulnerability, the model in short, and the secret-scan record. The full history was scanned with gitleaks on 2026-10-05 (17 commits, no leaks); `npm run scan:secrets` keeps the command. *(roadmap: Public release)*
- Settings file: `%APPDATA%\ai-command-center\settings.json` with `hubUrl` and `quickLinks` (`[{ "label", "url" }]`), read with neutral defaults by `src/shared/settings.js` (3 tests), so a fresh install needs no file. `ACC_HUB_URL` still overrides the Hub URL. The empty-state quick links are Project Hub and the Chrome Web Store unless the file says otherwise. *(roadmap: Public release)*
- CI: `.github/workflows/ci.yml` runs `npm run lint` and `npm test` on Ubuntu and Windows with Node 24 on every push and pull request, skipping the Electron download and install scripts, which the tests don't need. A separate job runs `npm audit` and may fail without failing the build, because `adm-zip` has open advisories with no fix. *(roadmap: Public release)*

- Cronsole in the app: a **Cron** tab in the sidebar lists Cronsole's scheduled tasks through Cronsole's own MCP server (its `list_tasks` tool), with the next run, or paused, missing or failed, on each row and the details on hover. The server is the script `ACC_CRONSOLE_MCP` names, run on the app's own Electron binary in Node mode over stdio, started on the tab's first open and stopped on quit; it reads `CRONSOLE_TOKEN` from the environment as it does under Claude Code. **Open Cronsole** or a click on a task shows Cronsole's UI (`ACC_CRONSOLE_UI`, default `http://localhost:7373`) in a pinned tab: first in the strip, no close button, reused rather than duplicated, and pinned again after a restart. The stdio JSON-RPC client is hand-written with no new dependency; `src/shared/cronsole.js` has it, with 6 tests, and `npm run smoke` checks the tab and the pinned tab against the running app. *(roadmap: Phase 2)*

- Chat panel: a **Chat** tab in the sidebar where Claude drives the app through its own MCP server, so a message can open a tab, search or open a file, or put a command on the terminal's Run bar. The key (`ACC_CHAT_API_KEY` or `ANTHROPIC_API_KEY`) and model (`ACC_CHAT_MODEL` or `ANTHROPIC_MODEL`) come from the environment, with no default model; the key stays in the main process. Tool calls go over HTTP with the MCP token, so they're logged in the MCP tab and `terminal_run` still waits for a click. Built on `fetch` with no new dependency. `src/shared/chat.js` has the turn loop, with 9 tests including one against a real MCP server; `npm run smoke` opens the tab. *(roadmap: Phase 2)*
- Drive the app from Claude Code: every terminal the app opens gets `ACC_MCP_URL` and `ACC_MCP_TOKEN` for this launch, and the README's new section registers the server once with `claude mcp add --scope user --transport http ai-command-center '${ACC_MCP_URL}' --header 'Authorization: Bearer ${ACC_MCP_TOKEN}'`. Claude Code expands the variables each time it starts, so the random port and token stop mattering; the section also covers using it from other terminals and the two expected ✗ rows a connect leaves in the MCP panel. The MCP server now starts before the shell loads, so the first terminal has the variables too. *(roadmap: Phase 2)*
- MCP call log: every request to the MCP server, answered, failed or refused (no token, wrong Host, bad JSON), shows newest first in a new **MCP** tab in the sidebar, with the tool, its arguments, time taken and any error, and is appended to `%APPDATA%\ai-command-center\logs\mcp.log` as one JSON line. Arguments and errors are clipped to 300 characters; the file moves to `mcp.log.1` past 5 MB. The server reports calls through an `onCall` hook in `src/shared/mcp.js`; `src/shared/mcplog.js` has the entry format, with 5 tests, and `npm run smoke` checks the panel against the file. *(roadmap: Phase 2)*
- Shell menu on the terminal strip: the ⌄ next to ＋ opens PowerShell 7, Windows PowerShell, Command Prompt or Git Bash, whichever are installed. Each is a fixed profile in `src/shared/shells.js` picked by id, so no message can name an executable or pass arguments; `terminal_run` only types into PowerShell sessions, checked in the main process. *(roadmap: Daily use)*
- Documents open under the app's own sidebar: clicking a file (or 👁 on any row) shows it in a tab as an `acc://doc/<Hub id>` page. Hub renders the Markdown through `/api/file`; other text shows as code, images inline, folders as a listing, and relative links and images resolve because the address mirrors the Hub id. One tab is reused as you click through; Ctrl+click opens another. The pages run no scripts, can't be framed, can't be reached from a web page, and serve only files in Hub's index. HTML files still open as pages, and VS Code moves to the hover buttons and the menu. *(roadmap: Daily use)*
- Right-click menu on Files rows: View here, open raw file or page in a tab, VS Code, Reveal in Explorer, Terminal here, Copy path, Copy Project Hub id. It's a native menu, so it draws over the browser pane. *(roadmap: Daily use)*
- `terminal_run` MCP tool: a bar over the terminal shows the command and which terminal it goes to, and nothing runs until you click Run. Run types the line into the active PowerShell (or a new one) and Deny, which has focus, returns a tool error; asks queue one at a time and expire after 5 minutes. The command stays in the main process, so the click only picks a terminal, and newlines, tabs, escapes, bidi overrides and zero-width characters are refused so what's shown is what runs. No process is started with arguments. It returns once the line is typed, without the output. `src/shared/confirm.js` holds the pending asks; 6 new tests, and `npm run smoke` calls the tool and clicks Run. *(roadmap: Phase 2)*
- Navigation MCP tools: `open_tab` takes what the address bar takes (URL, Windows path, `localhost:<port>`, host or search) and opens it as a tab, in the background if asked; only http, https and file pages, so about: and extension pages stay the user's. `open_file` opens a Hub node id from `sidebar_search` in VS Code or reveals it in Explorer, adds it to Recent like a sidebar click, and refuses paths, `..`, UNC and virtual ids and Hub's open-with-default-app, which would run a script without a click. 7 new tests; `npm run smoke` calls `open_tab`. *(roadmap: Phase 2)*
- Read-only MCP tools: `list_tabs` (id, URL, title, loading, active), `sidebar_search` (the sidebar's search over Hub's files, the chosen bookmarks source and Recent, with absolute paths and an `errors` list when Hub is down) and `recent` (filter by type, limit). They live in `src/shared/tools.js` with 8 tests; the sidebar and `sidebar_search` now share one `searchAll` in `src/shared/tree.js`, and `npm run smoke` calls all three against the running app. *(roadmap: Phase 2)*
- Control Center MCP server: the main process starts it on `127.0.0.1` with a random port and a fresh token each launch, writes both to `%APPDATA%\ai-command-center\mcp.json`, and removes the file on quit. Calls without the token get 401, and a non-loopback Host header gets 403. Built on `node:http` with no new dependency. *(roadmap: Phase 2)*
- `scripts/Start-AICommandCenter.ps1` starts the app through the repo's own `electron.exe` with no console window left open; the README has the shortcut target line. *(roadmap: Phase 1)*
- Browser tabs reopen after a restart: the URLs and the active tab are saved to `layout.json` when the window closes and restored once the shell is ready. Blank pages and disallowed schemes are dropped, and `src/shared/session.js` has 4 tests. *(roadmap: Phase 1)*
- Licensed GPL-3.0-or-later: `LICENSE` with the unmodified GPL-3.0 text, `package.json` updated, and a Licence section in the README explaining the GPL dependency. *(roadmap: Public release)*

**Fixed**

- Manifest V3 extensions whose background worker uses `browser.*` start instead of crashing on `browser.windows`. Chromium's native `browser` object is separate from the `chrome` object electron-chrome-extensions fills in; `src/preload/extension-browser.cjs` points one at the other in extension contexts only. LastPass's and Rakuten's workers now run; ADR-001 corrects the earlier diagnosis, which blamed Electron's preload support.
- The `adm-zip` advisories: electron-chrome-web-store, which unpacks Web Store installs, pins `adm-zip` `^0.5.16`, and every release up to 0.6.0 carried open advisories (8 Dependabot alerts, 5 high). A `package.json` `overrides` entry pins the patched `^0.6.1`. `npm audit` reports 0 vulnerabilities, so the CI audit job now fails the build instead of only reporting. `npm run smoke` still loads both installed extensions, and an extract round trip on 0.6.1 passes. *(roadmap: Public release)*
- A page's right-click "Open link in default browser" passed any link to Windows, so a `file:` or `ms-*:` link could launch a program; it's now http and https only. "Open link in new tab" now goes through the same navigation check as clicks.
- A second launch while the app was running started its own MCP server and overwrote `mcp.json` with a port that died a moment later. It now exits before doing anything else.
- `Start-AICommandCenter.ps1` no longer prints Electron's log output into the terminal it was run from; it goes to `%APPDATA%\ai-command-center\logs\launch.out.log` and `launch.err.log`.
- Closing the window or a tab no longer pops up "A JavaScript error occurred in the main process: Object has been destroyed". electron-chrome-extensions closes a tab again from its `destroyed` event, after the window is destroyed and the view's `webContents` is already undefined; `Tabs.close()` now skips whatever is gone.

## 0.1.0 — 2026-09-29

**Added**

- Requirements, three architecture options, and three ADRs: Electron shell, Project Hub over HTTP, terminal in the main process. *(roadmap: Phase 0)*
- One Electron 44 window with a sidebar, browser tab strip, address bar and terminal panel; the splitter sizes are remembered. *(roadmap: Phase 1)*
- Browser tabs in their own sandboxed session, with back, forward, reload, links opening as tabs, a context menu, and a button that opens the page in the default browser. *(roadmap: Phase 1)*
- Chrome extension support: the Web Store's install button works in a tab, and installed extensions load at start with their toolbar icons. *(roadmap: Phase 1)*
- PowerShell 7 terminals in tabs, openable in any folder from the sidebar. *(roadmap: Phase 1)*
- Files panel from Project Hub's scan, with open in VS Code, reveal in Explorer, and HTML files opening in a tab. *(roadmap: Phase 1)*
- Bookmarks panel reading Chrome, Edge or Brave through Hub, or Hub's favorites. *(roadmap: Phase 1)*
- Recent list of pages, files and terminals, and one search box across files, bookmarks and recent. *(roadmap: Phase 1)*
- `npm test` with 18 unit tests for the tree, URL and recent helpers, and `npm run smoke`, which launches the app, drives the sidebar, saves screenshots and quits. *(roadmap: Phase 1)*
- `npm run spike:extensions`, which installs LastPass and Rakuten and reports what happens.
- `npm run lint` (`node --check` over every JavaScript file), `CLAUDE.md` for the agent that works this repo each week, and `docs/product/` with the spec and build plan. *(roadmap: Phase 1)*

**Changed**

- Moved into the ai-automation-tools org pipeline: the repo is now `ai-automation-tools/ai-command-center` (private, transferred from a personal account the same day, with secret scanning, push protection and Dependabot alerts verified on) and the local clone sits in the org's `Draft/` incubator. *(roadmap: Phase 1)*
- The roadmap now marks everything above `## After public release` as a release gate; LastPass support, Mike's daily-use checks and Phase 3 moved below it.

**Fixed**

- The app no longer hangs on quit. node-pty's console-list helper crashed during shutdown (`AttachConsole failed`); the terminal now uses the bundled ConPTY, and the app exits explicitly once every window and session is closed.
- A long search result list no longer pushes the terminal panel off the bottom of the window.

**Known issues**

- LastPass and Rakuten install and show toolbar icons, but their background service workers crash on start: Electron 44 doesn't run preloads in extension service workers, so `chrome.windows` is missing. See [ADR-001](decisions/adr-001-electron-shell.md#spike-result-2026-09-29).
